# Plan: Dinamik DB Çift Dilli Destek (Plan 04-03 — v3.0)

## Current Objective
Supabase içerik tablolarına nullable `_en` kolonları eklemek, locale-aware sorgu yardımcısı yazmak, admin formlarına EN alanları eklemek ve public sorguları çift dilli hâle getirmek. Bu plandan sonra **DB içeriği de uçtan uca EN/TR**.

## Tasks
- [ ] 1. Supabase migration: `_en` kolonları (nullable, RLS'i bozmadan) — `profiles`(title_en,description_en), `about`(title_en,description_en), `projects`(title_en,description_en,category_en), `expertise`(title_en,description_en), `certificates`(title_en,details_en), `education`(title_en,description_en), `experience`(title_en,description_en).
- [ ] 2. `src/types/database.ts`: ilgili interfacelere `*_en?: string | null` alanları ekle.
- [ ] 3. `src/lib/supabase/localized.ts`: `localizedSelect(locale, baseCol, enCol)` → `coalesce(<en>, <base>)` ifadesi üretir; tablo bazlı yardımcılar.
- [ ] 4. Public sorguları güncelle: `[locale]/page.tsx`, `expertise`, `projects`, `certificates`, `contact` → locale'a göre EN/TR kolon (fallback TR).
- [ ] 5. Admin formları: ilgili `/admin/<entity>/{page,new}` + `actions.ts`'lere EN alanları ekle (TR/EN yan yana veya sekme UI) — about, profile, projects, expertise, certificates, education, experience.
- [ ] 6. Supabase'de örnek EN seed (en az birer kayıt) — manuel veya migration ile.
- [ ] 7. `npm run lint` + `npm run build`; EN/TR fallback UAT.

## Verification
- EN içerik dolu kayıtlarda `/en` EN gösteriyor; EN boşsa TR fallback (hata yok).
- Admin'den EN alanı düzenlenebiliyor ve kaydediliyor.
- RLS/izinler bozulmadı (admin hâlâ erişiyor, public hâlâ okuyor).
- Build temiz; TS hatasız.
